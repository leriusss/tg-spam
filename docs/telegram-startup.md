# Ограниченные повторы стартового getMe

Временная ошибка Telegram при создании BotAPI больше не требует немедленного
завершения процесса. Повторяется только синхронный конструктор до запуска listener
и recovery worker: максимум пять попыток, каждая с deadline 15 секунд, интервалы
1/2/4/8 секунд, общий бюджет 90 секунд вместе с запросами и ожиданиями.

Следующая попытка допускается только при наличии полного 15-секундного слота.
Из-за расхода общего бюджета попыток может быть меньше пяти. Более ранний deadline
вызывающего контекста также учитывается. После исчерпания попыток/бюджета ошибка
возвращается в main, который завершает процесс с прежним exit code 1.

## Граница зависимости и контекст

Используется прежняя зависимость
`github.com/OvyFlash/telegram-bot-api@v0.0.0-20251112155921-e82db5fd534b`.
Её `NewBotAPIWithClient` вызывает `GetMe`, который создаёт запрос с Background;
конструктор не принимает context. Scoped HTTP adapter подставляет контекст попытки
до существующего durable cooldown gate. Он сохраняется до чтения/закрытия body.
После успешного конструктора `BotAPI.Client` возвращается к исходному клиенту.
Временный адаптер не используется для последующих API-вызовов.

Отмена родительского контекста прерывает запрос, чтение body и timer ожидания,
не разрешая новую попытку. SIGTERM использует существующий обработчик main,
отменяющий этот же контекст. Инициализация не создаёт фоновых goroutine.
Транспорт — прежний net/http; повторные попытки переиспользуют его соединения,
каждый полученный body закрывается, включая ошибочные ответы.

## Классификация и 429

Повторяются типизированные timeout, connection reset/abort/refused, broken pipe,
EOF/truncated transport, временный DNS и HTTP 500–599. NXDOMAIN без признака
временности не повторяется. Неверная форма/пустой токен отклоняются без запроса;
400/401/403, постоянные TLS/certificate/configuration и нераспознанные постоянные
ошибки не повторяются. Поиск слов в сообщении ошибки не используется.

HTTP status перехватывается до JSON-декодирования зависимостью: HTML 5xx не теряет
свою категорию. Для 429 берётся максимум обычной задержки, JSON `retry_after` и
`Retry-After` (число секунд либо HTTP date). Если ожидание плюс следующая попытка
не помещаются, запуск завершается без нового запроса. Длинные значения, например
7200 секунд, сохраняются полностью в существующем durable cooldown при включённом
recovery; они не сокращаются до локального startup budget.

429 без достоверной положительной задержки, с неполным/невалидным либо превышающим
64 KiB JSON-ответом останавливает запуск безопасно, без угадывания короткого
интервала. Ошибка записи durable cooldown также останавливает запуск. Эти ответы
не приводят к бесконечным повторам. Значения, не представимые time.Duration,
нельзя использовать как локальное ожидание.

## Логи и проверки

Логи содержат attempt/max, безопасную категорию, retry_in и outcome. Ошибка
верхнего уровня не оборачивает сырые transport errors или Telegram descriptions:
URL/токен/заголовки/текст gateway не выводятся. Отмена и deadline сохраняют
стандартные errors.Is(context.Canceled/DeadlineExceeded).

`TestTelegramStartup*` проверяют настоящий конструктор, HTTP server и управляемое
время: все retry/permanent категории, 429 и budget, отмену запроса/чтения body/
ожидания, закрытие body и отсутствие токена в логах/ошибке. Тест `execute` работает
в subprocess с локальным HTTP mock и SQLite: до успеха нет polling/worker calls,
после успеха polling начинается один раз, сохранённый delete выполняется один раз
и подтверждается журналом; при 401 listener и worker не стартуют. Subprocess
изолирует существующие process-lifetime storage resources приложения.

Команда профильной проверки:

```sh
go test -race -count=1 -run '^TestTelegramStartup' ./app
```

Настроек или миграции БД не добавлено. Polling deadline, runtime HTTP client,
recovery/claims, auto-trust, Han, emoji-исключения и Docker policy сохраняются.
Это не исправление неизвестной первопричины сетевой задержки и не гарантия запуска
при длительной недоступности Telegram. Production и GHCR workflow этим PR не
меняются. Откат к прежнему бинарнику возвращает немедленное завершение при
первом startup timeout; конфиги и актуальные runtime-БД сохраняются.

## Optional route failover

See [Telegram routes](telegram-routes.md) for opt-in authenticated HTTPS CONNECT
fallback, diagnostics and the separate production transition runbook. It uses
the same startup attempt/total budgets and does not add retries within a request.
